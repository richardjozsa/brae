# rhoSimpleFoam findings — status board

From a source-level audit of brae against the six stock OpenFOAM v2412 rhoSimpleFoam tutorials, plus
direct matrix comparison against OpenFOAM (`tools/dumpScalarMatrix`).

**Ordered by expected field error, not by effort.** Fix top-down.

The dangerous class is not "missing feature" — it is **present, parsed, and never applied**, because that
converges to a plausible wrong answer and says nothing. Every fix in group A must either apply the input
or refuse the case; see `src/applications/solvers/common/brae_notice.cuh`.

stream instead of resolving each entry inside its own sub-dictionary. Any statement containing `Gauss` was

statement with its enclosing block and each rule fires only in its own. Unit test `scheme_blocks`, three

## E. Found by `dict_audit` — inputs read off disk and never used

`FoamDict` records every key it is ASKED for; `auditDict` walks the parsed dict afterwards and names
everything that was never asked. **The complement is the gap list.** On by default (`BRAE_DICT_AUDIT=0`
silences it) so it is visible during development, because "silently ignored" is the shape almost every
defect in this document has taken — A2, A3, A4, A5, A9, C1, C2, C4, C5, C6 are ten instances of it.

It reports, it does not throw: an unread key is EVIDENCE, not proof. Two known limits — a case brae
REFUSES (aerofoilNACA0012 on fvOptions) never reaches the audit, and a dict read twice via separate
`readDict` calls records its lookups on an object nobody audits.

## F. aerofoilNACA0012 — six defects the ducts could not expose

The stock `aerofoilNACA0012` tutorial diverged to NaN by iteration 7 while every duct in the suite
converged. It is the only case in reach that is simultaneously **fast** (|U| ~ 280 m/s, so `Ekp` is 57%
of `e`), **nearly singular in pressure** (`freestreamPressure` anchors the level with `Σ|iC| ~ 2e-3`
across the whole boundary), and **heavily rho-relaxed** (`relaxationFactors/fields/rho 0.01`). Each of
those three properties hid one or more of the following. Method: `cudafoam/solver-porting-dissection.md`.

| # | Finding | Where | Measured | Status |
|---|---|---|---|---|
| F1 | `alphat` never set by brae's `validate()`. OF's `rhoSimpleFoam.C:64` calls `turbulence->validate()` → `correctNut()`, whose compressible tail (`EddyDiffusivity::correctNut()`) sets `alphat = ρ·nut/Prt`. brae updated `alphat` only at the END of the outer iteration, so the FIRST energy solve ran on laminar diffusivity alone. Invisible wherever the turbulent part is small. | `device_simple_foam.cu` `validateTurbulence()` | `alphaEff` **3.59e-05 vs OF 1.67e-03 — 46x too small** | ✅ **FIXED** |
| F2 | `he` measured about the wrong reference. OF's `hConstThermo`: `Hs = Cp·(T − Tref) + Href`, `Tref` defaulting to `Tstd = 298.15`; `Ha = Hs + Hc()`, so the heat of formation `Hf` belongs to the ABSOLUTE enthalpy only. brae used `he = Cv·T` ("e") and `Cp·T + Hf` ("h"). **Not cosmetic**: the energy equation is not invariant under `he → he + C`; the shift injects a spurious source `C·div(φ)`, which cancels only at convergence — so it is invisible in a converged duct and fatal on a transient path. `Tstd` now resolves from `DimensionedConstants` like `RR`. | `thermo_model.cuh`, `thermo_parse.cuh`, `foam_constants.cuh` | brae−OF = **2.996407e+05** vs `Cp·Tstd` = 2.996408e+05 | ✅ **FIXED** + test `sensible_energy` (negative control: 9 assertions fail on the old formula) |
| F3 | `bound(field, SMALL)` applied to **every** transported scalar including `he`. | F4 | `linearUpwind`'s gradient ARGUMENT ignored. Fixing the cell half did **not** fix this. Two corrections worth recording, both instances of the anti-patterns in the method doc:
- F5/F6 were first attributed to the **kOmegaSST**, because at iteration 2 the only stages that
  disagreed were `muEff` and `alphaEff` (both ≈8.6e-01). Running `simulationType laminar` and

- A clean 0.853 scale factor on `phiHbyA` was an artefact of comparing `stage_fluxHbyA` (before the
  `interpolate(rho)` weighting) against OF's `phiHbyA0` (after it) — 0.853 is exactly `1/ρ̄`.

## Notes

- **brae's universal gas constant did not match OpenFOAM's.** brae used the CODATA-2018
  `RR = 8314.46261815324`; OF v2412 computes `RR = NA*k` from its own rounded constants
  (`NA = 6.022141793e23`, `k = 1.38065e-23`) and gets **`8314.47006650545`**, the pre-2019 value. Measured
  from OF itself with a purpose-built utility, not taken from a data sheet. The gap is **8.958e-07
  relative** and it propagates to `R`, `psi` and `rho` in every compressible case. brae's number was the
  more physically current one, and that is exactly why it was wrong: the contract is to reproduce
  OpenFOAM. Found as an unexplained 9.06e-07 floor on `rho` that SURVIVED after C5 made brae stop at OF's
  own iteration count — OF's written `rho` missed OF's own `p/(R·T)` by 8.958e-07 while brae's matched its
  own to 1e-11, which pointed at the constant rather than at convergence. Fix measured on `hf_vs_openfoam`:
  rho **9.06e-07 → 4.82e-08** (19x), rho at the inlet **9.00e-07 → 4.61e-09** (195x), T 4.94e-08 → 4.83e-08.
- Matrix assembly itself is verified: diagonal **1.76e-06** and source **6.66e-07** vs OF's
  `fvScalarMatrix` (`tools/dumpScalarMatrix`). The transport operator is not the problem.
- Compressible-specific BCs verified correct: `totalPressure` (ρ-weighted), `flowRateInletVelocity`
  (mass and volumetric), `freestream` base, `compressible::alphatWallFunction`, model `Prt` default 1.0.
